# 0.5.0 — Package Rename, Binary Releases, and First Publish

> **For agentic workers:** execute Phase A, stop for review, then Phase B only when told.
> Every task ends green: `cargo fmt --all -- --check`,
> `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`,
> `cargo check -p stitch-me-up-wasm --target wasm32-unknown-unknown`,
> `cargo +1.88.0 test --workspace`.

**Goal:** Ship `0.5.0` with crates.io-available package names, prebuilt binaries on GitHub
Releases, the manifest-warning cleanup, and the stale `verify-te2` branch removed.

**Non-goals:** no engine, layout, rendering, or CLI/WASM behavior change; no directory
renames; no change to the MSRV (1.88) or to library import paths.

## Decisions already made (do not re-litigate)

| Directory (unchanged) | Old package | New package | Lib target (unchanged) |
| --- | --- | --- | --- |
| `crates/stitch-core` | `stitch-core` | `stitch-me-up-core` | `stitch_core` |
| `crates/stitch-cli` | `stitch-cli` | `stitch-me-up` | bin `stitch-me-up` |
| `crates/stitch-wasm` | `stitch-wasm` | `stitch-me-up-wasm` | `stitch_wasm` |

- `[lib] name` is set explicitly so `use stitch_core::…` / `use stitch_wasm::…` and the
  generated `examples/web/pkg/stitch_wasm.js` path stay byte-identical.
- Workspace version becomes `0.5.0`; one release, no 0.4.3.
- Release artifacts: 3 native runners (`x86_64-unknown-linux-gnu`, `aarch64-apple-darwin`,
  `x86_64-pc-windows-msvc`), tar.gz/zip archives containing binary + README + LICENSE,
  plus `.sha256`, built on stable with `--locked` and stripped symbols.
- `release.yml` runs on tag push `v*` and `workflow_dispatch` (`dry_run` input), uploads to
  an existing GitHub Release, and waits briefly for it to appear.
- Publishing is manual: `cargo publish --dry-run` first, then real publishes in order.

## Global constraints

- Branch `release/0.5.0` from clean `main`; fast-forward merge at the end of Phase A.
- 104 tests must keep passing on stable and 1.88; no test edits except import/package names.
- Never move `v0.4.x` tags; never rewrite history.
- CHANGELOG describes only changes actually made.
